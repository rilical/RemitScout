# Gold Cache Batch Jobs

## Overview
Three batch jobs populate Gold cache tables from Silver data:
- `gold:popular-corridors`: updates `gold.popular_corridors` from `silver.recent_searches` and recent quotes.
- `gold:fx-rates`: updates `gold.fx_rates` with weighted FX averages.
- `gold:pulse-cache`: updates `gold.pulse_cache` entries used by the Pulse UI.

Each job uses distributed locking via Redis to avoid concurrent runs and supports graceful shutdown.

## How To Run
```bash
pnpm -C backend gold:popular-corridors
pnpm -C backend gold:fx-rates
pnpm -C backend gold:pulse-cache
```

## Environment Variables
- `GOLD_POPULAR_CORRIDORS_LOCK_TTL_SECONDS` (default: 600)
- `GOLD_POPULAR_CORRIDORS_MAX` (default: 100)
- `GOLD_FX_RATES_LOCK_TTL_SECONDS` (default: 300)
- `GOLD_PULSE_CACHE_LOCK_TTL_SECONDS` (default: 900)

## Pulse Cache Key Strategy
Pulse cache entries are keyed per filter so the UI can request corridor/timeframe/amount/method
variants without live Silver queries:

```
pulse:{key}|corridor={slug|global}|timeframe={24h|7d|30d|1y|max|all}|range={7d|30d|90d|365d|all}|amount={bucket|all}|payin={bank|card|cash|wallet|all}|payout={bank|cash|wallet|all}
```

Notes:
- `pulse:corridors` is unfiltered.
- Filtered keys are generated by `gold-pulse-cache` for each corridor, timeframe, amount bucket, and method pair discovered in Silver.
- `pulse:*` base keys are also stored for the default filter set:
  - `corridor=global`, `timeframe=30d`, `range=all`, `amount=1000`, `payin=bank`, `payout=bank`.
- API lookups use candidate fallbacks by progressively dropping filters if a specific key is missing.
- If a range-specific key is absent, the API falls back to `range=all` (default 30d window).
- When timeframe is omitted, the API defaults to `timeframe=30d` for cache lookups.

## Pulse Payload Coverage
`gold-pulse-cache` now seeds full Pulse payloads from Silver data:
- Charts: all IDs in `frontend/lib/pulseChartRegistry.ts`.
- Method coverage, table rows, and provider heatmap are provider-level (not synthetic).
- Market insights (smart send, market snapshot, true cost, market depth, arbitrage, bank comparison, cost trend, hero) are derived from recent Silver quotes.
- Payloads include `lastUpdated` where the UI displays trust stamps.

## Recommended Schedules
- `gold:popular-corridors`: every 15-30 minutes
- `gold:fx-rates`: every 10-15 minutes
- `gold:pulse-cache`: every 15-30 minutes

## Monitoring
Each job logs:
- `job_start` with lock info
- `[entity]_processed` and `[entity]_inserted` or `[entity]_upserted`
- `job_complete` with duration
- `job_failed` and `job_fatal_error` on failure

Lock keys:
- `gold-popular-corridors-job`
- `gold-fx-rates-job`
- `gold-pulse-cache-job`

## Troubleshooting
- If a job exits immediately with `lock_already_held`, check Redis connectivity and ensure no stuck lock.
- If a job logs SQL errors, validate Silver data freshness and schema changes.
- If `gold:pulse-cache` is missing keys, verify each query output and confirm the Pulse defaults still include any fallback entries.
